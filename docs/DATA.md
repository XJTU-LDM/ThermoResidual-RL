## Excluded Materials

No original field CSV/Excel files, measurement logs, private project reports,
account credentials, replay trajectories acquired from the field, or third-party
article PDFs are included. Original records remain governed by project and
institutional access restrictions. This repository neither grants access nor
creates a new permission route for those records. No private records are needed
for the documented simulation commands.

Model weights and effective fitted coefficients are derived artifacts, not raw
recordings. The confidentiality audit checks file inventory, text contents,
serialized checkpoint metadata and replay contents. Such a check is a release
screen, not a guarantee about the disclosure risk of arbitrary future model
training or contributions.

The original pressure forecasting fit requires controlled labels and acquisition
metadata; its architecture, inference and fitting implementation are provided,
but raw-label fitting cannot be reproduced using a synthetic example as a
substitute for the original data. Public model/control inference can be run
independently of that fitting step.

## Synthetic Dataset

`data/synthetic/synthetic_boundary.csv` is generated from a Physics-only closed
loop with a declared seed. Every row is labelled `data_type=simulation`.
`metadata.json` gives the model context, sample count and seed. Its source trace
retains physical residuals and a complete control response.

| Column | Unit | Definition |
|---|---|---|
| `time_s` | s | Simulation time at the end of the command interval |
| `pressure_MPa` | MPa absolute | Wellhead delivery-port pressure |
| `condenser_pressure_MPa` | MPa absolute | Simulated condenser pressure |
| `source_heat_kW` | kW | Heat extracted from formation into the source control volume |
| `water_exchange_kW` | kW | Simulated water-side exchange heat, a different control-volume quantity |
| `cooling_water_inlet_K` / `cooling_water_outlet_K` | K | Cooling-water temperatures |
| `command_power_kg_s` / `command_cooling_kg_s` | kg/s | Projected requests, not guaranteed delivery |
| `actual_power_kg_s` / `actual_cooling_kg_s` | kg/s | Actual branch delivery |
| `output_power_kW` / `output_cooling_kW` | kW | Reported filtered outputs used for tracking |

This is a boundary-like data product for inspection and reusable examples.
The controller simulator does not consume it as an imposed heat sequence:
the next heat and pressure depend on the new action and model state.

## Other Trace Fields

`target_*_kW` denotes the interval tracking target. `*_cost` and `reward` are
dimensionless scaled objective terms. `mass_residual_kg` and `energy_residual_kJ`
are numerical balance residuals. `energy_throughput_kJ` is the denominator used
for cumulative relative energy closure. `rate_violation` and `bound_violation`
are step flags; `mpc_fallback` flags an optimization fallback.
`supply_shortfall_kg_s` distinguishes a valid request from available supply.
`*_wall_s` is elapsed wall-clock time, which varies across computers.

Trace diagnostics such as `bulk_pressure_MPa` or `process_*_multiplier` are
written after plant advancement for analysis. Their presence in a CSV does
not make them controller inputs. The shared observable channels are specified
in `contracts.CHANNELS` and `control.ControlInterface`.
